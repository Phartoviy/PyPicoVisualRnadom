# Квантовый скаттерплот — Arduino IDE

Готовый скетч C++ для Raspberry Pi Pico / Pico W с **RP2040** и программа визуализации для ПК.
Pico 2 / RP2350 и пакет Arduino Mbed этим скетчем не поддерживаются.

## Установка пакета плат

1. Откройте Arduino IDE → Файл → Настройки.
2. В «Дополнительные ссылки для менеджера плат» добавьте:

```text
https://github.com/earlephilhower/arduino-pico/releases/download/global/package_rp2040_index.json
```

3. Откройте менеджер плат, найдите `pico` и установите пакет
   **Raspberry Pi Pico/RP2040/RP2350** от **Earle F. Philhower, III**.
   Название может немного различаться в зависимости от версии.
4. В Инструменты → Плата выберите **Raspberry Pi Pico** или **Raspberry Pi Pico W** согласно плате.
5. USB Stack: **Pico SDK**. Остальные настройки, включая частоту процессора, оставьте штатными.
   Отдельные библиотеки через менеджер библиотек не нужны: hardware/* входят в пакет плат.

## Открытие и первая загрузка

1. Распакуйте архив. Откройте файл:
   `firmware/QuantumScatterplot/QuantumScatterplot.ino`.
   Сохраняйте имя папки QuantumScatterplot совпадающим с именем скетча.
2. Закройте Thonny, screen, программу Python и другие приложения, занимающие порт.
3. Отключите Pico. Удерживая BOOTSEL, подключите USB; после подключения отпустите кнопку.
4. В Инструменты → Порт выберите **UF2 Board**, если он отображается, затем нажмите «Загрузить».
5. После перезапуска платы выберите появившийся COM-порт / `/dev/ttyACM0`.
   Следующие загрузки обычно работают без BOOTSEL. Если автосброс не сработал, повторите BOOTSEL.

Если UF2 Board не обнаруживается, выполните Скетч → Экспорт бинарного файла и скопируйте
созданный файл `.uf2` на диск **RPI-RP2**, появившийся после подключения с BOOTSEL.
Плата должна автоматически перезапуститься. Нужен USB-кабель с передачей данных.

Загрузка C++ прошивки заменяет MicroPython. Заранее сохраните нужные файлы с платы на ПК.
Для этой версии MicroPython и main.py не нужны. Для возврата можно установить MicroPython UF2
и повторно загрузить сохраненный main.py.

## Проверка потока

Откройте монитор порта Arduino IDE. Выберите 115200. Должны идти строки:

```text
# SOURCE ROSC
173
42
255
```

Числа в примере условные. `# SOURCE ADC` означает резервный источник.
Если монитор пуст, проверьте выбранную плату, USB Stack и порт.
Serial здесь — USB CDC; Serial1/Serial2 относятся к UART и не используются.
Перед запуском программы ПК **закройте монитор порта**.

## Программа ПК

Файл `pc/scatterplot.py` совпадает с предыдущим проектом. Можно использовать уже установленную версию.
Номер USB-порта после смены прошивки может измениться.

Linux, из корня распакованного проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m serial.tools.list_ports -v
python pc/scatterplot.py --port /dev/ttyACM0
```

Windows PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe pc\scatterplot.py --port COM3
```

Подставьте свой порт. Его также можно задать в переменной PORT в начале скрипта.
Требуется Python 3.10+ и графический сеанс. На Debian/Ubuntu для venv и GUI могут потребоваться
пакеты `python3-venv` и `python3-tk`. При отказе в доступе к порту проверьте его группу
(`ls -l /dev/ttyACM0`); для dialout выполните `sudo usermod -aG dialout "$USER"`,
после чего выйдите из пользовательского сеанса и войдите снова.

## Управление и поведение

- Space: пауза/возобновление графика. Прием и статистика продолжают работать.
- R в английской раскладке: сброс точек, статистики и незавершенной пары, также во время паузы.
- Закрытие окна: остановка чтения и освобождение порта.
- Ошибка порта: сообщение в терминале и повтор через 2 секунды.
- Нет чисел 5 секунд: повтор подключения. При смене номера порта измените --port.

X — значения №0, 2, 4…; Y — №1, 3, 5…; нумерация с нуля.
Хранятся последние 2000 точек, после заполнения старые исчезают.
При 100 числах/с получается до 50 точек/с и примерно 40 секунд истории.
Статистика вычисляется по всем корректным числам с последнего сброса.
Первая строка после открытия порта отбрасывается для синхронизации.
После обрыва незавершенная пара удаляется. Без номеров последовательности в протоколе
исходную четность после потери целой строки восстановить нельзя.

## Генерация и настройки

В начале .ino:

- `RATE_HZ = 100` — верхняя частота отправки (1…100).
- `FORCE_ADC = false` — true принудительно включает резервный источник для проверки.
- `SAMPLE_DELAY_US = 5` — интервал перед чтением исходного бита.
- `BYTE_TIMEOUT_US = 100000` — предел времени получения байта.

ROSC.RANDOMBIT читается через структуру регистров Pico SDK. В случае отключенного,
нестабильного или не выдающего достаточно меняющихся битов ROSC включается АЦП канала 4
(встроенный датчик температуры). `adc_read() & 1` берет младший бит исходного 12-разрядного отсчета.
Скетч использует АЦП монопольно; не добавляйте параллельный analogRead/ADCInput без согласования.

Корректор фон Неймана отбрасывает 00/11 и превращает 01/10 в 0/1; 8 принятых битов образуют байт.
Это уменьшает смещение при независимых стационарных исходных битах, но не гарантирует
независимость, равномерность или криптографическое качество. Таймаут обнаруживает
недостаток меняющихся битов, а не все возможные неисправности источника.
При недостаточном шуме АЦП выводится диагностика вместо подставных чисел.
Фактическая частота может быть ниже 100 чисел/с из-за источника, коррекции и USB.
Системное тактирование не следует переключать на ROSC.
«Квантовый» — название проекта, а не доказательство квантовой природы случайности.

## Проверка и ограничения проверки

```bash
python -m unittest discover -s tests -v
```

В архив включены 8 тестов ПК: разорванные строки, диапазон, буфер, пары, статистика,
пауза/сброс и повтор подключения. Компиляция под реальное ядро Arduino-Pico и загрузка
на физическую плату в среде подготовки архива не выполнялись: toolchain и плата отсутствуют.
